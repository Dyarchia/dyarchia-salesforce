The release-coupled facts that apply across the whole platform. Individual skills state only the
deltas specific to their own domain and point here for the rest, so a version bump is one edit
instead of a sweep across every skill.

## What "API version" means here

Salesforce ships three releases a year. Winter '27 is **API version 68.0**, generally available in
waves through 3 and 10 October 2026.

The number that governs behaviour is **the API version compiled into each individual class, trigger,
component or page** — not the org's release. An org on Winter '27 still runs a class stamped 55.0
under 55.0 semantics. Raising that stamp is a deliberate, testable act: it can change security
defaults and break code that compiled fine before.

## Security defaults from API 67.0 onward

These flipped in Summer '26 (67.0) and still hold in 68.0. They are the single most common source of
"it worked before I bumped the version" bugs.

| Behaviour | Below 67.0 | 67.0 and above |
|---|---|---|
| SOQL, SOSL and DML access mode | System mode | **`USER_MODE`** — object and field permissions plus sharing are enforced |
| Class with no `with sharing` / `without sharing` keyword | Inherited from caller | **`with sharing`** |
| `WITH SECURITY_ENFORCED` in SOQL | Supported | **Removed — does not compile** |
| `with sharing` / `without sharing` on a trigger | Tolerated | **Illegal — does not compile** |

Triggers themselves always run in **system mode**, in every API version. Sharing and field
permissions are not enforced for you inside a trigger; enforce them explicitly when the work is on
behalf of a user.

Migration order when raising a class to 68.0: replace `WITH SECURITY_ENFORCED` with `WITH USER_MODE`
(or `Security.stripInaccessible` where partial results are acceptable), state the sharing keyword
explicitly rather than relying on the new default, then re-run tests as a non-admin user. Server-to-
server code that assumed system-mode access can silently return fewer rows rather than fail loudly.

## What Winter '27 adds

Status is stated because it decides whether an agent may propose the feature. **Beta and Developer
Preview features are not available in production orgs** — proposing them as a default produces code
that does not deploy.

| Change | Status | Notes |
|---|---|---|
| Apex heap: 10 MB synchronous, 25 MB asynchronous | GA | Up from 6 MB / 12 MB. An org setting can hold the old limit during transition |
| Only invalid Apex classes and triggers recompile on deploy | GA | Cuts deploy time in large orgs |
| `explicitNamespace` on `Database.QueryOptions` | GA | Stops subscriber custom fields shadowing packaged ones |
| `lwc:external` for third-party web components | GA | Removes the iframe workaround |
| Complex JavaScript expressions in LWC templates | GA | Component `apiVersion` 66.0 or higher |
| REST API `/latest` endpoint alias | GA | Convenient for exploration; pin an explicit version in production |
| Apex Symbol API (Tooling API REST) | Beta | Compiler-grade type metadata for IDEs and AI tooling |
| `FORMULA()` in a SOQL `WHERE` clause | Beta | API 68.0+, **sandbox / Developer Edition / scratch orgs only** |
| `@IntegrationTest` — real HTTP callouts in tests | Developer Preview | Async only, one concurrent test, no automatic rollback |
| Flow Test Mode inside Flow Builder | Beta | Declarative Flow tests earn **no** Apex code coverage |

## Retirements and enforcements in Winter '27

These break running integrations rather than merely deprecating a pattern.

- **The OAuth 2.0 username-password flow is retired.** A connected app still using it simply stops
  receiving tokens after the upgrade, with no warning. Migrate to JWT bearer or another supported
  flow. See `dya-integration-auth`.
- **Profile filtering is enforced.** A user without one of the bypass permissions (View All Profiles,
  Customize Application, Manage Users and five others) can no longer see other users' profile names;
  queries return empty rather than erroring. See `dya-permissions`.
- **SOAP `login()` requires the "Any API Auth" user permission**, and is on its way out entirely for
  API 31.0–64.0. See `dya-integration-auth`.
- **View Setup Audit Trail** becomes a standalone permission instead of riding on a broader one.
- **Experience Delivery (Beta) is discontinued**, with auto-migration on republish through October
  2026. See `dya-lwr-sites`.

No retirement date has been announced for Aura or Visualforce. Both remain supported; both are in
maintenance mode, which is a reason to build new work in LWC, not a deadline.

## HTTPS

Every external endpoint and resource must be HTTPS. There is no supported way to call an HTTP
endpoint from Salesforce.
